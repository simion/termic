# i18n: how termic speaks two languages

React-i18next with bundled TS locale modules. No network loading, no JSON
imports: every locale is a TS module under `src/locales/<lang>/<ns>.ts`,
aggregated by `src/locales/en.ts` / `src/locales/zh-CN.ts`. Setup lives in
`src/lib/i18n.ts`; read its header comment first, it is the contract.

## Languages

The pref is `uiLanguage` in localStorage (store/prefs.ts), three values:
`system` (default; any Chinese `navigator.language` maps to zh-CN), `en`,
`zh-CN`. `applyLanguage()` swaps i18next's language AND `<html lang>` so
WKWebView's font fallback picks CJK faces for Chinese. Resources are bundled,
so `useSuspense: false` — a translation is always synchronous, Suspending
would blank the UI for a frame.

## Namespaces

`common` (defaultNS: OK/Cancel/Save/shared one-word labels), `sidebar`,
`settings`, `dialogs`, `task` (core task panes: tabs, terminals, file tree),
`panels` (content panels: diff, git, PR, race), `chrome` (root components,
views, ui primitives), `backend` (everything outside React: stores, lib,
hooks — toasts, notifications, confirm dialogs, tab titles).

`src/locales/parity.test.ts` flattens both trees and pins the key sets and
the `{{placeholder}}` sets per key identical, and requires the namespaces in
its `EXTRACTED` list to be non-empty. A namespace is not "done" until it is
in that list. A missing key renders the key itself, which is the dev-time
signal that a string was wired without a locale entry.

## Wiring rules

- One `useTranslation("<ns>")` per string-rendering component, placed BEFORE
  any early return. Sub-components in a file that render strings get their
  own hook; do not thread `t` through props to reach them.
- Outside React (stores, lib, hooks): `import { i18n } from "@/lib/i18n"` and
  `i18n.t("backend:key")`. No live re-render on a language switch — accepted
  for toasts, notifications and tab titles, which are minted at event time.
  A pure helper that renders for a component should take `t` as a parameter
  instead, so the component's subscription re-renders it (see
  `promptTitle(p, t)` in store/prompts.ts, `groupLabel` in views/History.tsx).
- Strings computed inside `useMemo`/`useCallback`: add `t` to the deps array
  (react-i18next gives it a new identity per language change, so rows
  recompute). NEVER add `t` to an effect whose deps spawn a PTY or fetch —
  use `i18n.t` there instead (TerminalPane's spawn effect is the example:
  a `t` dep would respawn every terminal on a language switch).
- Embedded markup (`<b>`, `<kbd>`, `<code>`) uses `<Trans>` with
  `components={{ 1: <b /> }}`, and the locale key text carries matching
  `<1>...</1>` tags. EN and ZH MUST keep the same tag indices.
- Plurals: separate `*_one` / `*_other` keys, picked with an explicit
  ternary on the count, passing `count` to `t()` for interpolation. Not
  i18next's suffix auto-selection (zh has no plural distinction; explicit
  beats clever here).
- Tab titles and clone suffixes are DATA minted at creation: translated at
  creation time with `i18n.t`, never re-resolved afterwards. A stored
  override always wins over a lookup.

## Conventions

- `data-testid` values NEVER change with language — specs depend on them.
- Raw backend errors stay raw: `pushToast(String(e))` is a passthrough, not
  copy. Same for CLI output quoted verbatim (the Codex YOLO note quotes
  `requirements do not allow sandbox_mode` because that substring is how the
  user matches it; `src/lib/agents.test.ts` pins it in BOTH languages).
- Brand names (Termic, Claude, Codex, Gemini, Docker, GitHub, GitLab, Touch
  ID) stay English in zh-CN. zh-CN tone follows VS Code / Linear: agent =
  智能体, worktree = 工作树, main checkout = 主检出.
- No em dashes in ANY locale string (project copy rule; the parity test does
  not catch this, agents.test.ts's note test is the pattern for pinning it).
- Placeholder vocabulary for fixtures and examples is in CLAUDE.md (Fixtures);
  locale strings that name a path use `~` or a `{{var}}`, never a real one.
